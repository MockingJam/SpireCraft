# SpireCraft 阶段性代码 Review（2026-11-27）

> **基线**：`main` @ `bcebfbf`（Glory G1–G4 合入之后）。
> **范围**：整个仓库，包括 Java 源码、手写与生成的资源、世界生成数据、`tools/`、构建脚本与 CI、`docs/` 下全部文档，以及 GitHub 上全部 issue 和 PR 的讨论。
> **方法**：按 9 个方向分别审阅：核心机制、武器、生物、世界生成、注册与资源、架构与端侧安全、构建与仓库、文档与共识、设计闭环。每条发现都由另一位审阅者回到代码逐行复核，复核不通过的剔除；复核后又补审了 3 个遗漏领域（客户端渲染与专用服务器、手写数据包与生成文件、结构模板与生成脚本）。
> **数字**：共 148 条发现，其中 143 条通过复核（属实 74，部分属实并改写 69），驳回 5 条。这是去重前的数字，同一个问题被几个方向分别报告时按多条计。按复核后的严重度：critical 0、major 12、minor 71、nit 60。12 条 major 合并重复后是第 2 节的 11 条。
> **局限**：以静态阅读为主，唯一真正跑过的是一次 `gradlew assemble`（通过，产物 `spirecraft-0.1.0.jar`，5.0 MB）。没有进游戏，也没有启动专用服务器。下文写“玩家会遇到……”的地方都是读代码推出来的，修的时候请进游戏走一遍确认。

## 0. 结论

**代码底子比预想的好，大方向也守住了。问题主要在三处：**

1. **数据驱动怪物系统（`ScriptedMonster` / `ScriptedDefs`）和生成脚本有几处静默失效**：招式附带的效果被丢掉，阶段、库存等状态不存档，Boss 房的闸门会提前打开；模型生成链漏加载了一批精修模型，女王城堡的宝库箱子被脚本覆盖掉了。这些问题出错时不会报错，只能靠玩家实际打一遍才发现。
2. **共识定下来了，但没有闭环**：owner 在 #26 里逐条拍板的规则（一回合 = 3 秒、Boss/精英标签等）既没有回写文档，也没有落实到代码。`glory.md` 标题还写着“待确认”，内容却已经全部上线，5 个待确认问题没有答案。
3. **文档分层失效**：早期策划（`ARCHITECT.md`）、过期交接（`HANDOFF.md`）、v1 群系稿和懒人包 README 跟现行文档并排放着，都没有“已废弃”标记。新协作者，包括下一次开工的 AI，读到的很可能是作废的方案。

**没有发现**会让专用服务器崩溃、损坏存档、或让一整个系统不能用的问题。客户端/服务端隔离、网络包线程、datagen 与生成资源的同步都做得扎实，详见第 5 节。

## 1. 总体评价

### 1.1 代码质量

- **端侧安全**：common 代码里没有直接引用 `net.minecraft.client.*`。`ClientSetup.init` 只在 `FMLEnvironment.dist.isClient()` 时调用，网络包用 `consumerMainThread`，事件处理大多先判断 `isClientSide()` 或 `ServerLevel`。Buffer/Artifact 的层数扣减统一推迟到 `ServerTickEvent.Post`，避开了在伤害处理中途重入。
- **资源一致性**：`en_us` 和 `zh_cn` 各 684 个键，逐键对应。所有物品都有获取途径，没有孤儿贴图，也没有缺失的模型或战利品表。提交的 `.cache` 让 `runData` 能自动删掉过期的生成文件。
- **薄弱点**：
  - 数据驱动怪物系统的招式语义和存档（第 2 节第 1–4 条）。
  - 少量静态可变状态在集成服务端的客户端/服务端两个线程之间共享，或不随登出、换存档清理（第 3.6 节）。
  - 几个上千行的大类（`V2Features` 1457 行、`SpireStructures` 1192 行、`ScriptedDefs` 813 行），以及重复的 worldgen 辅助函数。
  - 删除功能时没有顺手清理引用：“流沙洞穴”已经删了，物品说明、刷怪表和注释里还在引用它。

## 2. 需要优先修的问题（major）

> 按“玩家会不会碰到”排序。行号以 `bcebfbf` 为准。

### 2.1 多层无限时长的 Artifact 抵挡一次后整层消失

- **位置**：`effect/StackChanges.java:51`；调用方 `mob/ScriptedMonster.java:130`、`mob/Chomper.java:44`
- **原因**：怪物出生时用 `duration = -1`（无限）添加 Artifact。`apply()` 先 `removeEffect`，再判断 `if (newAmplifier < 0 || old.getDuration() <= 0) return;`。无限时长的 `getDuration()` 恒为 -1，所以剩余层数永远加不回去。
- **后果**：机甲骑士（精英，3 层）、永世沙漏（Boss，3 层）、噬咬者（2 层）抵挡第一个负面效果之后，Artifact 就整个没了。
- **建议**：改为判断 `old.getDuration() == 0`，或者先判断 `!old.isInfiniteDuration()`。重新添加时保留 -1。

### 2.2 SHOT / LOB 招式的附带效果被静默丢弃

- **位置**：`mob/ScriptedMonster.java:208-211, 226`；定义在 `mob/ScriptedDefs.java:265, 308, 330, 438, 486, 491`
- **原因**：`applyEffects` 的条件排除了 SHOT 和 LOB。弹丸命中时 `SpireBolt.hit()` 只按弹丸种类施加固定效果，不读招式里的 `fx` / `poison`。
- **后果**：
  - 追踪手的 0 伤害弹丸成了完全无效的空招。
  - 利齿之眼的昏眩变成了脆弱。
  - 异蛙寄生虫的 3 层毒只剩 2 层。
  - 乐加维林族母、猎人杀手、虱虫之祖的虚弱和脆弱全部丢失。
  - 结果就是玩家看到的意图和实际效果对不上。
- **建议**：让弹丸携带发射者招式的效果参数，命中时施加。定义阶段对“0 伤害又无效果”的招式直接报错。

### 2.3 DASH 招式的后半段永远不触发效果和自我强化

- **位置**：`mob/ScriptedMonster.java:193, 202-205, 231`；`mob/ScriptedDefs.java:80-81`
- **原因**：DASH 的 `hitTicks()` 有两次触发（`{0, 6}`），但 `m.hits` 仍是默认的 1。`lastHit = hitIndex() == m.hits - 1` 在第 0 次冲刺时为真，但冲刺分支直接 return 了；第 1 次真正撞击时又为假，于是附带效果和第 231 行之后的自我效果全部被跳过。
- **后果**：
  - 瀑布巨兽冲撞不加蒸汽层数，“蒸汽爆炸”的节奏被削弱。
  - 熟睡甲虫翻滚不加力量。
  - 枭法官 13 伤害招式的易伤永远不上身。
- **建议**：以 `hitTicks().length` 作为唯一的计数来源判断 `lastHit`。

### 2.4 `ScriptedMonster` 的关键状态不写存档

- **位置**：`mob/ScriptedMonster.java:643-668`
- **原因**：只保存了 Opener/Loop/State/Ritual/Steam/Plating/Slippery/Revivals/Once。没有保存 `phase`、`stockLeft`/`stockGen`、`growCount`、`curl`、`downTicks`、`stolen`。读档时还会 `& ~DOWN`，把倒地状态清掉。
- **后果**：
  - 实验体打到第 3 形态后退出重进：外观还是第 3 形态，行为却回到第 1 形态，下次死亡会再进一次阶段转换。
  - 斧头机器人的库存在重载后回满。
  - 倒地状态的怪重载后以 1 血爬起来。
  - 小偷偷走的物品在区块卸载后永久消失（见第 3.3 节）。
- **建议**：补上这些字段的读写。读档时如果 STATE 带 DOWN 位，就恢复 `downTicks`，不要清掉。

### 2.5 女王战里火炬头融合体一死，闸门就全开了

- **位置**：`mob/ScriptedMonster.java:619-620`；`mob/ScriptedDefs.java:722, 726, 736`
- **原因**：`die()` 只要求 `wakeRoom > 0` 且当前是最后阶段，就打开 40 格内所有闸门，不检查同一个房间里是否还有别的 Boss 活着。女王和融合体的 `wakeRoom` 都是 14；融合体活着时女王不动，所以融合体必然先死。
- **后果**：融合体一死，闸门就开了，女王还在场。玩家可以出门，女王 30 秒后回满血重新沉睡。“关门打 Boss”在最终战里失效。
- **建议**：开门前确认半径内没有其他活着的 `wakeRoom` Boss，或者在 Def 上标一个负责开门的 Boss。

### 2.6 技能伤害被当成近战命中，主手武器的命中效果串到技能上

- **位置**：`weapon/Abilities.java:113`、`weapon/Orbs.java:163`、`weapon/DirgeFlute.java:115`；判断在 `weapon/WeaponEvents.java:113`、`effect/SpireEffectEvents.java:89`
- **原因**：特斯拉线圈、暗黑球爆发、挽歌笛子都用 `indirectMagic(player, player)`，直接实体和来源实体都是玩家。`WeaponEvents.onHurt` 和 `isAttack` 都会因此把它当成近战命中。
- **后果**：主手拿着带毒匕首、镰刀、君王之剑之类的武器时，暗黑球爆发（本身不需要手持任何东西）会给范围内每个敌人叠毒、叠灾厄、加伤害，镰刀还会触发横扫；地狱之刃“下一击强化”会被球爆发消耗掉。这些技能伤害还会吃力量、虚弱、易伤和荆棘。
- **建议**：技能伤害改用 `indirectMagic(null, player)` 或自定义伤害类型。`onHurt` 只认近战伤害来源。同时在文档里写清楚技能伤害吃不吃力量和易伤。

### 2.7 熔岩石的 Boss 标签漏了末影龙和 9 个模组 Boss

- **位置**：`src/main/resources/data/spirecraft/tags/entity_type/bosses.json`；使用方 `item/MaterialEvents.java:98`
- **现状**：标签只有凋灵、远古守卫者、监守者，以及 4 个早期模组 Boss。用 `.boss()` 定义的墨影幻灵、同族神官、瀑布巨兽、乐加维林族母、无厌沙虫、女王、火炬头融合体、永世沙漏、实验体都不在里面，末影龙也不在。
- **后果**：熔岩石对这些 Boss 不生效，跟 `materials.md` / `lore.md` 的说法矛盾。
- **建议**：用 datagen 根据 `def.boss` 自动生成这个标签，同时按 #26 一-11 的答复新建 `spirecraft:elites`。如果确实有意不包括末影龙，就改文档。

### 2.8 owner 在 #26 里拍板的规则没有落地

- **位置**：#26（OPEN，没有后续评论）、`docs/design/effects.md:3, 21`、`effect/SpirePoisonEffect.java:13`
- **owner 已经回答、而且能对照代码确认还没落实的**：
  - 一-1：一回合 = 3 秒。现状：`effects.md` 仍写“N × 5 秒（暂定）”，中毒间隔仍是 100 tick，没有全局的回合常量。
  - 一-6：N 层 = N 回合 = N × 回合秒数。现状：没有按回合常量换算。

## 附录 B：复核时被驳回的发现

- **武器**：“充能球状态在重生时没有清理，HUD 可能残留旧球”。驳回：`WeaponEvents.java:54` 在死亡时调用 `Orbs.clear` 并同步一个空列表，登录时（`:55`）也会同步一次。
- **世界生成**：“把黑森林换成密林，使林地府邸只能在苍白之园生成”。驳回：这是 owner 在 v2.4 做的决定（`WorldPresetProvider.java:50` 附近的注释），`structures.md:319` 也写明了代价和替代方案。
- **注册与资源**：“`src/generated/resources/.cache` 被提交进仓库”。驳回：这是 Forge datagen 的标准做法，提交它才能让 `runData` 自动删除过期文件。
- **设计闭环**：“角色建筑离出生点太远，跟已确认的每约 50 区块一座的密度不符”。驳回：`structures.md:313-322` 里 15000 格以上的数据是调整群系之前的实测，修复后最近的一座约在 1200–1360 格。

## 附录 C：方法

- 9 个审阅方向，每个方向的发现都由一位独立复核者回到代码逐条确认：属实的保留，部分属实的改写，无法确认的剔除，并重新评定严重度。复核之后又由一位“完整性检查”审阅者找出 3 个没覆盖到的领域补审。
- 严重度：**critical** = 崩溃、专用服务器无法运行、存档损坏、或一整个系统不能用；**major** = 玩家会遇到的明显 bug，或者跟 owner 决定、设计文档直接矛盾，或者阻碍协作的矛盾；**minor** = 真实存在但影响有限；**nit** = 值得顺手清理的小问题。
- 实际运行过的只有构建：系统 JDK 21 加 `-g <Lazypack 缓存的绝对路径>` 执行 `gradlew assemble` 通过；不加 `-g` 在 worktree 里会失败（见 3.7）。jar 里包含 `dev/SelfTest`、`dev/ClientShots` 和 datagen 的 `.cache/`。dev 代码只在 `SPIRECRAFT_SELFTEST` / `SPIRECRAFT_SHOTS` 环境变量存在时才运行，玩家环境默认不会触发。
- 原计划另请 Codex 做一轮独立审阅，但这台机器没有安装 Codex CLI，所以这一轮没有做。
